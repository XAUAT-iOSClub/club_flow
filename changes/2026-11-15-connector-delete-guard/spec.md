## 1. 背景与问题

连接器版本以 `(id, version)` 为主键，工作流冻结版本则在 JSON DSL 的步骤 `uses` 中引用连接器。数据库外键无法表达这层关系，直接删除连接器可能让历史冻结版本无法指定运行或回滚。

## 2. 目标

- 提供可供未来接口层调用的安全删除服务。
- 任一冻结工作流版本仍引用目标版本时拒绝删除，并返回定位信息。
- 保证并发删除不会产生部分成功或重复删除。

## 3. 非目标

不新增 REST API、软删除字段、数据库迁移、发布模块或前端页面，也不改变 DSL 与权限契约。

## 4. 范围

| 类型 | 内容 |
|---|---|
| 涉及模块 | `packages/server/src/modules/connectors`、包根导出与集成测试 |
| 数据模型变更 | 无 |
| 接口变更 | 新增内部 TypeScript 服务及领域错误，无 HTTP 接口 |
| 前端配合 | 无 |
| 外部依赖 | 复用现有 Prisma、Vitest 与 PostgreSQL |

## 5. 方案要点

删除服务在事务内锁定目标连接器，读取所有冻结版本的顶层步骤 `uses`，精确匹配连接器 ID 与版本；存在引用则回滚，否则物理删除。历史冻结版本也纳入保护，草稿不参与判断。

## 6. 验收标准

- [x] 未引用版本可删除，其他版本不受影响。
- [x] 当前或历史冻结版本引用均阻止删除，并给出工作流、版本和步骤定位。
- [x] 草稿、不同版本、不同连接器及非法格式不误报。
- [x] 并发删除一个成功、一个返回不存在错误。
- [x] Node 22 下完整测试、类型检查与构建通过。

## 7. 开放问题

发布与回滚实现时必须遵守 `FOR SHARE` 锁协议，具体接入随对应模块计划完成。
