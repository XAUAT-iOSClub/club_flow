# 连接器版本删除引用保护 · 技术设计

## 1. 方案概述

新增 `deleteConnectorVersion(connectorId, version)`，由服务自己管理事务。事务先以 `FOR UPDATE` 锁定目标行，再检查冻结工作流版本中的引用；发现引用时抛出领域错误，未引用时删除并返回连接器。该方案不需要变更表结构，也不会改变现有草稿和运行数据。

## 2. 关键设计

### 2.1 数据模型

不修改 Prisma Schema，不新增迁移。保护范围是所有 `workflow_versions.dsl`，不包含 `workflows.draft`。历史版本仍可能指定运行或回滚，因此不能排除。

### 2.2 接口

包根导出以下内部能力：

- `deleteConnectorVersion(connectorId, version): Promise<Connector>`。
- `ConnectorVersionNotFoundError`：目标不存在。
- `ConnectorVersionInUseError`：包含连接器坐标及只读引用数组。
- `ConnectorVersionReference`：记录工作流、冻结版本、步骤、actionKey 与原始 `uses`。

本轮不定义 HTTP 状态码；未来 REST 层再根据统一错误契约映射。

### 2.3 模块改动

核心代码位于 `src/modules/connectors/delete-connector-version.ts`，事务复用 `withTransaction()`。SQL 通过 `jsonb_each(dsl->'steps')` 只读取顶层步骤的字符串 `uses`，不扫描 YAML、layout、草稿或步骤内部 `with` 数据。

解析时以第一个 `.` 分隔连接器与 actionKey，以最后一个 `@` 分隔版本。actionKey 可含点；版本只接受无多余符号的十进制整数。目标版本的任一 action 被引用都视为冲突。

### 2.4 关键流程与并发

1. 事务内锁定并确认目标连接器版本存在。
2. 查询所有冻结版本的步骤 `uses` 并精确筛选。
3. 有引用则抛出错误并回滚；无引用则按复合主键删除。
4. 删除行锁使并发删除串行，后执行者得到不存在错误。

发布与回滚侧后续必须在同一事务中按固定顺序对所需连接器执行 `FOR SHARE`，再写入冻结版本。共享锁与删除的排他锁配合，防止检查与删除之间新增引用。

## 3. 安全与权限

当前仅提供内部服务，不暴露网络入口。未来 REST 接入必须沿用 rank ≥ 30 的管理员写权限。错误仅包含工作流和步骤定位，不读取或输出 manifest 中的认证信息与密钥。

## 4. 备选方案与取舍

| 方案 | 优点 | 缺点 | 是否采用 |
|---|---|---|---|
| 删除前引用检查 | 无迁移，行为直接，保留物理删除能力 | 写入侧需遵守锁协议 | 是 |
| 软删除 | 可保留下架记录 | 需重新定义列表、运行、回滚与注册语义 | 否 |
| 规范化引用表与外键 | 数据库约束完整 | 改动范围大，需同步编译与发布流程 | 否 |

## 5. 兼容、迁移与回滚

无数据库迁移和旧数据改写。代码回滚只需移除服务与导出；当前没有调用方，不影响在跑运行。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 绕过服务直接 SQL 删除 | 仍可能产生失效引用 | 统一通过服务删除，后续接口禁止绕过 |
| 发布侧未遵守锁协议 | 并发预检与删除存在竞态 | 将 `FOR SHARE` 列为发布/回滚强制接入约束 |

## 7. 测试策略

使用 Vitest 与真实 `clubflow_test`，覆盖正常删除、领域错误、当前与历史引用、定位信息、误匹配、并发删除和包根导出；测试造数统一加独立前缀并自动清理。
