# archive · 已归档的变更计划

本目录存放**已结束**的变更计划，用于追溯「当时为什么这么改」。

## 规则

1. **只读**：归档后不再修改文档。需要修正历史时，新建计划并在 `spec.md` 中链接旧计划。
2. 归档前必须完成：
   - `plan.md` 的 `status` 为 `done` 或 `abandoned`；
   - `plan.md` §6「归档记录」填写归档日期、结论、验收结论与遗留问题；
   - `test/results.md` 有最终执行记录。
3. 使用 `git mv` 保留历史：

   ```bash
   git mv changes/2026-11-15-example-change changes/archive/
   ```

4. 保留原目录名与全部文件，不裁剪、不合并、不改写标题。
5. 同一主题再次启动时，新建计划目录，并在新 `spec.md` 里链接归档计划。

## 归档条件

| 情形 | 处理 |
|---|---|
| 已交付并通过验收 | `status: done`，归档 |
| 明确放弃 | `status: abandoned`，在 `plan.md` 写明原因，归档 |
| 被新计划取代 | 旧计划 `status: abandoned` 并链接新计划，归档 |
| 长期阻塞且无恢复计划 | 记录阻塞原因后归档，重启时新建计划 |
